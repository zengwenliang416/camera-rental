# Requirements: redesign-admin-device-schedule-v2

## Summary

将现有管理端设备排期记录页升级为设备排期 V2 工作台。工作台服务当前租户的唯一
仓库，面向管理者监督设备容量、有效占用、物流过程、待分配订单和异常风险。页面
不得重复员工端扫码发货、回仓登记、检测或维修操作。

## Users & Actors

- 租赁运营：搜索设备和订单、查看排期、物流与异常、选择后端推荐候选并确认分配。
- 租赁主管：查看容量和风险，处理排期冲突，并按最终确认的锁定规则管理设备。
- 仓库员工：继续在员工端执行扫码出库、回仓、检测和维修；本页面只读取结果。
- camera-rental-server：权威计算有效占用、候选资格、冲突、指标和预计释放状态。
- 快递100物流链路：提供去程和返程物流摘要、轨迹、风险与刷新结果。

## In Scope

- 在现有 `/rental/schedule` 路由内提供单仓设备排期工作台，不增加仓库选择器。
- 默认 30 天时间轴，并提供 14 天精确视图和 90 天长租视图；支持上一窗口、下一
  窗口、回到今天、横向滚动、跨月标题、左右延续标记。
- 时间轴以设备为行，以服务端返回的有效占用为条带；计租周期和设备占用周期分别
  展示，冲突判断只使用设备占用周期。
- 设备列表支持数百台规模的服务端分页，页大小为 25、50、100；支持按设备编号、
  序列号和型号关键词搜索，并按型号、设备状态和物流状态过滤。
- 顶部指标展示总设备、可排设备、占用设备、运输中设备、待分配订单、排期相关
  异常和利用率；所有值由后端按同一查询窗口返回。
- 待分配队列按订单明细和剩余数量展示。部分分配的订单继续保留，直到所有明细
  `remainingQuantity` 为零。
- 设备候选由后端按型号、启用状态、设备状态、有效占用、物流风险和最终确认的
  分类锁定记录筛选。前端只展示候选理由，最终分配仍调用现有事务接口并刷新工作台。
- 设备锁定使用统一分类记录，类型至少包括订单预留、回仓待检测、维修隔离和主管
  人工保留。每条记录保存设备、类型、原因、关联订单/明细、操作人、开始、计划结束、
  实际解除、状态和租户审计信息。
- 活动锁定设备不进入候选推荐。订单预留和主管人工保留支持明确的计划结束时间；
  回仓待检测在检测完成时自动解除，维修隔离在维修流程明确恢复可用时自动解除。
- 运营人员可在排期页创建订单预留或主管人工保留，并按权限提前解除；系统自动
  创建的回仓待检测和维修隔离锁定不得通过普通人工解除绕过仓库流程。
- 冲突与异常队列统一展示被拦截的候选冲突、返程延迟、回仓待检测、物流风险以及
  会影响分配的人工复核；候选冲突不得写入有效排期。
- 订单、设备和物流详情使用右侧抽屉。物流详情复用现有快递100摘要、轨迹和刷新
  能力，并同时展示去程、返程、最近节点、风险和预计释放时间。
- 有效占用从设备发货出库开始，持续到设备回仓且检测完成。去程运输、客户持有、
  返程运输和已回仓待检测均计入占用；检测不通过后设备进入维修/隔离且不可推荐。
- 当前租户只有一个仓库。`warehouseCode` 可作为后端内部关联字段，但页面不提供
  跨仓筛选或调拨决策。

## Out of Scope

- 员工扫码发货、打包复核、客户退回登记、回仓签收、设备检测和维修执行。
- 跨租户、跨仓库库存协调或仓库切换。
- 前端自行计算设备可用性、冲突、利用率或预计释放。
- 自动修改订单计租周期或金额。
- 以渠道订单 VO 替代内部租赁订单和明细的权威契约。
- 第一阶段新增持久化冲突表；异常队列优先由现有排期、物流、分配和复核数据派生。

## UI Design Impact

- Foundation spec: `openspec/specs/ui-design/design.md`
- 复用管理端 `ContentWrap`、Element Plus 表格、分页、表单、标签、抽屉、加载和
  错误模式，保持现有 RuoYi Pro 管理端密度。
- 页面结构为过滤区、指标区、设备时间轴、待分配订单、推荐结果、异常队列和右侧
  详情抽屉，不引入第二套 UI 框架。
- 状态必须使用文字和图形语义，不只依赖颜色；设备编号、订单号和物流单号使用
  等宽数据样式。
- 桌面端为主要操作面，窄屏保持可访问但允许时间轴区域内部横向滚动，页面本身
  不出现无界横向溢出。

## Theme & Locale Capability Impact

- Theme support: `light-dark`。
- Theme toggle policy: 复用管理端现有用户主题开关，不在排期页建立第二套开关。
- Internationalization: `enabled`。
- Supported locales: `zh-CN,en`。
- Default locale: `zh-CN`，fallback 为 `zh-CN`。
- Prototype coverage: 已批准原型的中文浅色桌面主流程作为布局依据；生产验收覆盖
  管理端现有 light/dark、`zh-CN`/`en`、窄屏、加载、空、错误、无权限和冲突状态。

## Architecture & Database Impact

- Foundation spec: `openspec/specs/system-architecture/design.md`
- 后端在 `yudao-module-rental` 增加面向工作台的查询 Service 和 VO；Controller
  不直接访问 Mapper，查询遵循租户隔离和 `rental:schedule:query` 权限。
- 日历以设备分页为主查询单位，后端批量读取设备、有效排期、订单明细、分配、
  Delivery 关系、物流摘要和检测状态，禁止按设备逐行发起 N+1 查询。
- 候选查询只返回服务端判定的资格和理由；现有事务性分配服务继续负责锁行、
  重查重叠和写入排期。
- 第一阶段不新增冲突持久化表；新增独立 `rental_device_lock` 业务锁定记录。
- 创建、解除和自动转换锁定必须在事务中锁定设备，并拒绝相互冲突的活动锁定。
- 日期按 `Asia/Shanghai` 处理；内部占用区间保持半开区间
  `[occupyStartDate, occupyEndDateExclusive)`，界面显示为包含首尾的业务日期。

## Frontend-Backend Data Flow Impact

- Foundation spec: `openspec/specs/frontend-backend-data-flow/design.md`
- `FLOW-SCHEDULE-WORKBENCH-QUERY`：前端提交窗口、设备分页、关键词和状态过滤；后端
  返回指标、设备行、条带、待分配摘要和异常摘要。
- `FLOW-SCHEDULE-DETAIL`：点击设备、排期条、订单或异常后，按 ID 加载订单、设备
  和物流详情；各抽屉独立处理加载、空、错误和无权限状态。
- `FLOW-SCHEDULE-CANDIDATES`：选择待分配订单明细后请求候选；后端返回资格、排除
  原因、相邻排期和物流风险。
- `FLOW-SCHEDULE-ASSIGN`：用户确认候选后调用现有分配写接口；成功后重新查询工作台，
  冲突或陈旧结果必须刷新候选并要求再次确认。
- `FLOW-SCHEDULE-DEVICE-LOCK`：主管创建订单预留或人工保留时提交设备、类型、原因、
  关联订单和计划结束；后端锁定设备并创建活动记录。人工解除只允许人工类锁定，
  自动类锁定由检测或维修流程解除。
- 物流刷新调用现有 Delivery tracking refresh 接口，不直接调用快递100。

## Component Architecture Impact

- Foundation spec: `openspec/specs/component-architecture/design.md`
- `index.vue` 只协调 URL 查询、请求状态、选择状态和抽屉，不承载时间轴绘制或业务
  资格算法。
- 提取指标、筛选、设备时间轴、待分配、推荐、异常队列、订单抽屉、设备抽屉和
  物流抽屉组件。
- 复用 `ContentWrap`、`Pagination`、Element Plus 控件、现有订单详情展示模式、
  `rentalLabels` 和日期格式化能力。
- `scheduleModel.ts` 只负责日期窗口、显示裁剪、列布局和服务端 read model 到视图
  模型的纯转换；不得判断权威冲突或候选资格。
