## Why

当前管理端设备排期页只是排期记录分页表，无法让运营人员在数百台设备和跨月长租
场景中快速判断容量、物流风险、待分配订单和设备释放时间。已确认的设备排期 V2
原型需要落到现有 Vue 3 + Element Plus 管理端，并由后端提供权威日历读模型和分配
候选结果。

## What Changes

- 将现有 `/rental/schedule` 改造成单租户单仓的设备排期工作台。
- 提供 14、30、90 天设备时间轴、横向滚动、跨月连续条带和数百设备服务端分页。
- 支持按设备编号、序列号、型号、设备状态、物流状态和时间范围检索。
- 增加实时容量指标、待分配订单、候选设备推荐和排期相关异常队列。
- 使用右侧抽屉展示订单、设备、占用、物流轨迹和预计释放信息。
- 继续复用现有事务性设备分配接口作为最终权威写入点。
- 增加面向工作台的后端聚合查询接口，不让前端计算权威可用性或冲突。
- 不在管理端重复员工端扫码发货、回仓、检测和维修执行流程。

## Capabilities

### New Capabilities

- `admin-device-schedule-workbench`: 管理端设备排期 V2 的日历、搜索、分页、待分配、
  推荐、异常和详情工作流。

### Modified Capabilities

- 无。

## Impact

- 后端：`camera-rental-server/yudao-module-rental` 的排期、设备、订单、分配和物流
  管理端读模型及测试。
- 前端：`camera-rental-admin` 的排期 API 类型、页面模型、组件、国际化和测试。
- API：新增排期工作台聚合查询、待分配订单、设备候选和设备详情接口；保留现有
  `/rental/device/assign` 写接口。
- 数据库：是否增加业务设备锁定记录仍待确认；其余第一阶段优先使用现有订单、
  设备、排期、分配、物流和检测数据生成读模型。
