# 闲管家售后同步

## 范围

普通订单状态和售后订单状态分别同步。首期只读查询售后列表、详情和拒绝原因；
同意退款、拒绝退款属于写操作，默认禁用。

已于 `2026-07-25` 重新核对当前在线接口：

| 接口 | 方法与路径 | 首期状态 |
| --- | --- | --- |
| 售后列表 | `POST /api/open/trade/refund/list` | 启用 |
| 售后详情 | `POST /api/open/trade/refund/detail` | 启用 |
| 同意退款 | 写接口 | 禁用 |
| 拒绝退款 | 写接口 | 禁用 |
| 拒绝原因 | 只读参数字典 | 后续按需启用 |

售后列表支持 `order_no`、`authorize_id`、`apply_time`、`refund_time`、
`refund_type`、`refund_status`、`page_no` 和 `page_size`。分页大小和页码均
最大 100，响应使用 `has_next_page`。

详情请求当前只要求：

```json
{"order_no":"<external-order-no>"}
```

## 建议保存字段

- 售后单号。
- 关联外部订单号。
- 售后状态。
- 退款金额。
- 申请原因和拒绝原因。
- 平台更新时间。
- 原始售后 JSON 和哈希。
- 最近同步时间、转换版本和异常原因。

押金退还、租金退款和设备赔偿必须使用不同内部业务类型。

## 当前实现

后端已实现只读售后同步：

- 管理端手动同步和定时同步复用同一套 `XianyuAfterSaleAdminService`
  入库逻辑。
- 每个售后列表页先保存为 `AFTER_SALE_PAGE` 原始证据，再保存列表 item
  `AFTER_SALE_LIST_ITEM`，随后按 `order_no` 补拉 `AFTER_SALE_DETAIL`。
- 标准化 `xianyu_after_sale.raw_payload_id` 指向详情原始载荷；列表页和列表
  item 仍保留在受限原始载荷表中，用于审计和重放分析。
- `xianyuAfterSaleSyncJob` 由芋道 `infra_job + Quartz` 调用
  `syncAfterSalesIncremental()`，遍历 `VALID` 且未过期的店铺授权。
- 增量窗口同时按 `apply_time` 和 `refund_time` 查询，降低只看申请时间漏掉
  后续退款状态变化的风险；两类窗口全部成功后才推进 `AFTER_SALE` 游标。
- 售后列表接口没有 `count` 字段；当 `has_next_page=true` 超过配置的
  `max-pages-per-shop` 时，本次窗口失败并不推进游标，避免把未拉全的数据标记
  为已同步。
- cron 在管理端“基础设施 -> 定时任务”维护；当前租户必须同时在闲管家配置中
  开启同步任务，否则 Job 安全跳过。

## 当前契约歧义

官方售后列表 / 详情 Markdown 中，`refund_no`、`order_no`、部分枚举字段的
OpenAPI 类型被渲染为空对象，但示例和值域表现为字符串或整数；`refund_amount`
在售后接口中标为整数，但没有像订单接口一样明确标注单位。

因此首期实现必须：

- 为售后接口保留完整原始 JSON。
- 对订单号和退款单号使用可接受 JSON 字符串 / 整数并标准化为字符串的解析器。
- 对枚举使用可接受整数值的宽容解析，同时保留未知原值。
- 在未取得更明确文档或真实脱敏样本前，不把售后 `refund_amount` 静默当成分；
  保存原始整数和单位确认状态。
- 若关联订单详情中的 `refund_amount` 已明确为分，可用于一致性核对，但不能覆盖
  售后原始值。

## 人工边界

自动同意或拒绝退款默认关闭。未来如需自动决策，必须单独设计金额上限、
允许状态、人工审批、幂等、审计和补救流程。

## 快递公司字典

快递公司查询属于“其他”只读接口，已于 `2026-07-25` 复核：

```text
POST /api/open/express/companies
```

当前后台仍实时查询该字典，并把完整响应以 `EXPRESS_COMPANIES` 保存到受限
原始载荷表；标准化字段只用于列表展示，不会触发订单发货。

## 测试

- 售后与普通订单状态隔离。
- 退款金额不覆盖实付金额。
- 重复售后推送幂等。
- 文档异常类型的宽容解析和原值保留。
- `has_next_page` 分页终止和最大页边界。
- 写操作授权缺失时拒绝执行。
