# 闲鱼 / 闲管家集成

## 权威来源

闲管家官方接口总索引：

```text
https://s.apifox.cn/3ac13d69-5a38-4536-ae9b-a54001854ef8/llms.txt
```

实现任何接口前必须读取总索引并打开目标接口的 Markdown 文档。在线文档优先于旧代码、历史聊天内容和字段名猜测。

## 集成边界

闲管家客户端应集中放在后端租赁模块的 `integration/xianyu` 下：

```text
integration/xianyu/
├── client
├── config
├── dto
├── convert
├── webhook
├── service
├── enums
└── exception
```

业务 Service 不得直接拼签名或发送 HTTP。签名、序列化、超时、错误转换和基础重试由集成客户端统一处理。

## 首期只读范围

首期优先支持：

- 店铺查询和授权状态
- 商品列表、详情和规格查询
- 订单列表和详情查询
- 售后列表和详情查询
- 快递公司查询

商品创建、编辑、库存修改、上下架、删除、订单发货、订单改价和退款属于写操作。除非用户明确授权，不得调用；默认不得在真实店铺自动化测试。

管理端权限按业务入口拆分：闲管家凭据、授权和集成配置页面仅允许超级管理员访问；
订单发货与发货图片识别属于渠道订单操作权限，挂在“渠道订单”菜单下，可授权给租赁
运营员工。员工发货仍必须通过后端 `rental:xianyu:ship` 和
`rental:xianyu:ship:ocr` 权限校验，不能通过隐藏配置页面间接控制。

## 订单同步

推荐采用：

```text
订单推送 + 定时增量同步 + 订单详情补拉
```

同步流程：

1. 接收并保存原始推送。
2. 使用外部订单号执行幂等检查。
3. 拉取订单详情。
4. 保存渠道订单、原始数据和语义明确的商品/SKU 标识。
5. 精确检查当前租户内的 `shop_id + xianyu_item_id` 处理规则。
6. `CONFIG_SKIPPED` 保留渠道订单、原始数据和实付金额，但不解析备注、不创建
   内部租赁订单、不创建转换复核、不生成排期。
7. 其他已付款订单立即幂等创建同一个内部租赁订单和明细，即使备注、型号或日期
   尚未齐全。
8. 保存备注解析快照，按精确商品/SKU 规则补充设备型号，计算准备状态。
9. 只有型号、计租周期和设备占用周期完整时才允许分配和排期。
10. 后续订单详情、商品/SKU 同步或配置变化调用同一重评服务，更新允许变化的计划。
11. 通过增量任务补偿推送遗漏和状态变化。

分页任务必须固定同步边界，保存安全游标，处理相同更新时间的多条记录，并区分接收数量、去重数量和失败数量。

历史补建不重新发明同步或转换逻辑。它对已持久化渠道订单固定
`xianyu_order.id` 上界并按主键升序分页，逐批调用同一
`RentalChannelOrderReconciliationService`。每批业务变更和 checkpoint 在同一事务
提交；失败批次整体回滚并保存安全错误记录，游标停在失败批次之前。dry-run 执行
真实 reconciliation 后回滚业务变更，只持久化任务游标和计数。详细操作见
`docs/integrations/xianyu/historical-reconciliation.md`。

## 金额和备注

- `pay_amount` 是否为分或元必须以当前目标接口文档确认；进入内部系统后统一转换为整数分。
- 备注为空或解析失败不能导致订单从总租金中消失。
- `seller_remark` 只用于提取发货、收货、计租和发回日期。
- 明确租期优先；没有明确租期时，收货次日开始计租，发回当天计租。
- `SELLER_REMARK_V6` 支持完整年份、中文日期、可选井号、计租 / 用机同义词，
  以及出库、到货、归还等物流同义词；对已确认的历史固定模板可做确定性位置推断。
  明确的“某日自提”同时作为出库日和收货日，日期与“自提”之间允许不含数字的短
  姓名或城市描述；缺少发回日时不得自动补全。
- 已识别的计租或物流日期会先保存供管理端复核，但缺少发货、收货、发回等关键
  日期时仍标记 `PENDING`，不得自动排机或转换。
- `SELLER_REMARK_V6` 将物流日期早于订单日期标记为
  `FAILED / LOGISTICS_DATE_BEFORE_ORDER`，将收货、发回等日期顺序冲突标记为
  `FAILED / INVALID_LOGISTICS_RANGE`，不静默猜测或无条件推到下一年。
- 解析版本升级后，历史订单按批次重算；重算成功时重新触发内部订单转换，并关闭
  仍开放但已失效的订单转换复核。
- 原始备注、解析结果、解析版本和错误原因必须一起保存。

商品映射不是内部租赁订单创建的前置条件。普通已付款订单先创建内部订单，再根据
配置补齐型号和准备状态：

- 单型号商品只按当前租户内的 `shop_id + xianyu_item_id` 命中。
- 多型号商品必须再精确命中订单中的闲管家 `sku_id`；只有商品规格同步保存的唯一
  关系可以补充闲鱼 `xy_sku_id`。
- 多型号 SKU 缺失、未同步、未配置或映射停用时保持 `WAITING_MODEL`，不得回退到
  商品级默认型号，也不得根据标题、`sku_text` 或商家编码猜测。
- 普通发货、设备分配和排期只能消费已经达到 `READY` 的权威准备状态。两条受控例外
  必须由发货确认页显式触发：一是订单仅因 `PRODUCT_RULE_NOT_CONFIGURED` 缺少商品
  型号规则时，具有 `rental:xianyu:ship` 和 `rental:configuration:update` 权限的
  操作员可确认创建当前 `shop_id + xianyu_item_id` 对应扫描设备型号的
  `CREATE_RENTAL + SINGLE` 规则，并在同一发货事务中重评至 `READY`；二是型号已确定、
  但准备状态为 `WAITING_REMARK` 时，具有发货权限的操作员可确认先发货、后补租期，
  创建 `DISPATCHED_PENDING_PLAN` 无排期分配并记录真实出库时间。后续备注补齐后由
  重评事务创建排期并恢复 `DISPATCHED`。已有规则、停用规则、`CONFIG_SKIPPED`、
  `MULTI`、SKU 缺失、型号冲突、订单关闭/退款或其他准备失败不得由发货流程覆盖。

配置或备注变化只能修改计划层。已分配、已出库、已回仓、已检测、已换机或已结算
事实由各自业务流程维护；出现不一致时保留原履约事实并进入人工复核。

## 租赁配置边界

管理端配置统一位于：

```text
/admin-api/rental/configuration/**
```

权限：

- `rental:configuration:query`：读取设备目录、可配置店铺、商品规则、同步 SKU、
  影响预览和重评结果。
- `rental:configuration:update`：创建、修改和启停目录或商品规则，以及控制历史
  补建任务。

商品规则写入前必须读取新的影响预览。后端接受规则变更后创建持久化异步重评任务，
前端轮询 `PENDING`、`RUNNING`、`SUCCEEDED`、`COMPLETED_WITH_ERRORS` 或 `FAILED`
状态及八类计数。相同租户或规则存在活动任务时，新的规则写入会被拒绝，避免多个
重评任务竞争覆盖结果。

## 推送回调

推送必须由后端接收：

1. 按官方文档验证签名或身份信息。
2. 保存脱敏后的原始请求。
3. 生成幂等键。
4. 快速返回平台要求的响应。
5. 通过异步任务拉取详情并处理业务。
6. 支持失败重试和人工重放。

生产和测试回调地址必须隔离，并使用 HTTPS。

## 凭据和日志

AppKey、AppSecret、签名、完整请求头和真实客户隐私不能进入 Git、前端、普通日志、
测试 Fixture 或文档。商家凭证和业务开关由管理端按租户写入
`xianyu_application`，AppSecret 加密保存且永不回显；后端不提供环境变量或 Spring
配置绑定兼容入口。数据库字段加密主密钥仍由通用基础设施配置注入。
