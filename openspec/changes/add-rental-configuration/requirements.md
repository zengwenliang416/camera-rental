# Requirements: add-rental-configuration

## Summary

在管理后台“租赁运营”下新增独立“租赁配置”页面，统一维护设备大类、设备型号、
设备编号前缀、闲鱼商品过滤规则、闲鱼商品/SKU 到设备型号的精确映射，以及卖家
备注书写规范。

同时修复闲鱼订单标准化和转换链路：分别保存闲管家商品/SKU 标识与闲鱼
`item_id`/`xy_sku_id`，普通订单详情落库后立即幂等创建内部租赁订单；备注和型号
允许后续增量补全。任何缺失标识不得互相回退或根据标题、规格文本猜测，任何自动
更新不得覆盖已经发生的设备分配、出库、换机、回仓、检测和结算事实。

## Users & Actors

- 租赁配置管理员：维护设备目录、商品处理策略、单型号或多型号映射和启停状态。
- 订单运营：查看订单的商品/SKU 标识、备注解析状态、型号匹配状态和待补全原因。
- 设备运营：创建具体设备时选择已配置目录；处理换机、冲突和已履约订单的人工复核。
- 相机租赁后端：同步渠道商品、SKU 和订单，保存明确标识，幂等创建并增量更新内部订单。
- 闲管家开放平台：提供订单详情、商品详情和多规格商品的规格列表。

## In Scope

### Rental Configuration Page

- 在“租赁运营”下新增独立菜单“租赁配置”，页面分为：
  - 设备目录：设备大类、设备型号、设备编号前缀、排序和启停。
  - 渠道商品规则：店铺、闲鱼商品 ID、商品标题、处理策略、型号识别模式、启停和备注。
  - 闲鱼备注规范：常用模板、特殊情况说明和一键复制。
- 设备大类和型号的新增、编辑、启停入口从“租赁设备”迁移到“租赁配置”。
- “租赁设备”仍可读取目录用于筛选和创建设备，但不再提供快捷新增大类或型号。
- 配置读取和修改使用独立权限；页面处理 loading、empty、error、permission 和窄屏状态。

### Product Handling Rules

- 规则唯一匹配范围为当前租户内的“店铺 + 闲鱼 `item_id`”，不能跨店铺复用。
- 每个商品选择一种处理策略：
  - `CREATE_RENTAL`：普通租赁商品，创建内部订单并解析备注、匹配型号。
  - `CONFIG_SKIPPED`：明确不进入租赁履约的商品，保留渠道订单、原始载荷和实付金额，
    不解析备注、不创建人工复核、不创建内部租赁订单、不生成排期。
- `CONFIG_SKIPPED` 初始配置包含以下 29 个闲鱼商品 ID：
  - 小疆：`1062409679830`、`1061015327345`、`1042851395917`、
    `1021749783370`、`1015758423054`、`996427340341`、`994967964760`、
    `980821925580`、`946426581576`、`969348191931`、`964654687997`、
    `989974832741`、`984580566155`、`930100016211`、`983025637118`、
    `985707224806`、`986580601148`。
  - 发发：`1024163647751`、`1022288043626`、`1018390062846`、
    `1017700474288`、`1015971948191`、`997210149459`、`994824734648`、
    `995640812523`、`946905413897`、`977248345425`、`957670857301`、
    `942506886325`。
- 初始数据写入前必须用当前环境的权威店铺记录将“小疆”“发发”唯一解析为内部
  `shop_id`；无法唯一解析时阻止该店铺规则写入，不能按名称模糊匹配或跨店生效。
- 新增、修改或启用规则后，系统异步重评受影响的尚未完成订单；已转换、已分配、
  已出库或已有其他履约事实的历史记录不能因命中过滤规则而自动删除、关闭或逆转。

### Exact Product and SKU Mapping

- 单型号商品使用 `店铺 + 闲鱼 item_id -> 设备型号`。
- 多型号商品使用 `店铺 + 闲鱼 item_id + 闲管家 sku_id -> 设备型号`，并在已同步
  规格存在唯一关系时同时保存、展示闲鱼 `xy_sku_id`。
- 多型号配置只能从该店铺、该商品已同步的 SKU 列表选择；不允许手工输入任意 SKU
  标识，不允许用 `sku_text`、商品标题或商家编码猜测型号。
- 单型号和多型号模式互斥。多型号商品没有 SKU、SKU 未同步、SKU 未配置或映射停用时，
  订单保持“待型号配置”，不能回退到商品级默认型号。
- 配置页展示闲管家 `product_id`、闲鱼 `item_id`、闲管家 `sku_id` 和闲鱼
  `xy_sku_id` 的明确标签，避免继续使用语义含混的“外部商品 ID/外部 SKU ID”。
- 型号规则新增或变化后：
  - 尚未分配具体设备的订单自动补全或更新型号。
  - 已分配或已出库订单不自动更换型号或设备；发现不一致时进入人工复核并保留原履约。

### Channel Identifier Normalization

- 订单详情 `goods.product_id` 保存为闲管家商品 ID，`goods.item_id` 保存为闲鱼商品 ID，
  `goods.sku_id` 保存为闲管家 SKU ID；字段缺失时保持为空并记录明确原因。
- 商品详情 `publish_shop.item_id` 必须按店铺落库；商品规格
  `sku_items[].xy_sku_id` 必须与闲管家 `sku_id` 一起落库。
- 不允许 `product_id` 与 `item_id`、`sku_id` 与 `xy_sku_id` 之间回退、互填或复用。
- JSON 和前端类型中的所有外部长整型标识使用字符串，避免 JavaScript 精度损失。

### Immediate Internal Order Creation

- 未命中过滤规则的渠道订单在订单详情成功持久化后，立即幂等创建一个内部
  `rental_order` 和一个对应明细；缺备注、备注解析失败、缺租期或缺型号都不能阻止创建。
- 实付金额始终来自 `pay_amount` 并进入内部租赁订单；备注不能修改金额。
- 内部订单和明细允许型号、计租日期和占用日期暂为空，并提供明确的准备状态和原因码。
- 只有型号、租期和占用日期完整且不存在冲突时，订单才可进入设备分配和排期。
- 同一“店铺 + 外部订单号”在同步重试、推送重放、详情补拉和历史回填中只关联同一
  内部订单，不重复创建。

### Remark Parsing and Incremental Updates

- 每次订单详情同步都保存原始备注、解析版本、解析结果、错误原因和变更历史。
- 页面展示并支持一键复制以下基础格式：
  - `发货M.D/收货M.D/发回M.D`
  - `自提M.D/发回M.D`
  - `发货M.D/收货M.D/租期M.D-M.D/发回M.D`
- 特殊情况在完整基础备注末尾追加：`续租`、`早退`、`改期`、`换机`、`损坏`、
  `遗失`、`逾期`、`物流延误`。
- 新备注解析成功时更新同一内部订单的计划日期；新备注为空、不完整或解析失败时，
  保留上一次有效日期，不能用空值或失败结果清除正确数据。
- 发回日期变晚识别为续租，变早识别为早退，多个计划日期整体变化识别为改期。
- `换机`、`损坏`、`遗失`、`逾期`、`物流延误`只创建运营提示或复核，不直接
  推断具体设备、赔偿金额或实际履约状态。

### Fulfillment-Safe Update Policy

- 计划日期、实际履约事实和变更历史分层保存。
- 未分配设备时，有效备注和型号配置可自动更新订单明细。
- 已分配但未出库时，日期变更必须重新检查设备占用冲突；无冲突才更新有效排期，
  有冲突则保持原有效排期并进入人工复核。
- 已出库后的续租锁定当前设备并检查未来排期；无冲突可延长预计占用，有冲突进入
  人工复核，不能自动换机或覆盖后续订单。
- 早退只更新预计发回日期；设备必须在实际回仓且检测完成后才释放占用。
- 换机必须关闭原设备分配并创建新的分配记录，保留两台设备及其排期历史，不能覆盖
  原 `device_id`。
- 实际出库、实际回仓、检测、退款和人工结算只来自对应权威业务操作，备注不能生成
  或覆盖这些事实。

### Historical Reconciliation

- 对现有普通未转换渠道订单执行可恢复、可统计、幂等的批量补建，先创建内部订单，
  再按已有备注和映射补全。
- 对命中过滤规则且尚无内部订单和履约事实的历史渠道订单标记 `CONFIG_SKIPPED`。
- 已有关联内部订单、分配、排期、出库、回仓、检测或结算记录的历史订单不自动逆转。
- 补建任务输出扫描、跳过、创建、更新、冲突、失败和待复核数量；失败不推进越过该
  记录的不可恢复游标。

## Out of Scope

- 不通过标题、SKU 文本、商家编码或备注猜测设备型号。
- 不从订单详情虚构闲鱼 `xy_sku_id`；只有规格同步的唯一关系可以补充该字段。
- 不根据备注自动选择具体设备、自动执行换机、自动确认回仓/检测或自动计算赔偿。
- 不删除渠道订单、内部订单、分配、排期、原始载荷或历史变更记录。
- 不调用闲管家商品编辑、库存、上下架、发货、改价或退款等第三方写接口。
- 本变更不修改客户 uni-app、员工端或 PC 官网。

## UI Design Impact

- Foundation spec: `openspec/specs/ui-design/design.md`
- Required UI decisions:
  - 管理后台使用现有 Element Plus、`ContentWrap`、表格、表单、抽屉/对话框、
    权限指令和通知模式。
  - 桌面端以三个明确区块或标签页组织配置，窄屏改为卡片/纵向表单，不能产生页面级
    横向滚动。
  - 标识列使用等宽数据样式和复制操作；状态同时使用文字与标签，不仅依赖颜色。
  - 多型号商品采用可展开 SKU 子表，未配置、停用和冲突状态可直接定位。
  - 危险变化提示影响范围，并要求确认；成功提示必须等待后端接受。

## Theme & Locale Capability Impact

- Theme support: `light-dark`
- Theme toggle policy: 复用管理后台现有 `theme-toggle:user`，本页不创建第二套切换器。
- Internationalization: `enabled`
- Supported locales: `zh-CN,en`
- Default locale: `zh-CN`
- Prototype coverage: 展示 light/dark、`zh-CN`/`en`、桌面/窄屏，以及 loading、
  empty、error、permission、单型号编辑、多型号展开和危险变更确认状态。

## Architecture & Database Impact

- Foundation spec: `openspec/specs/system-architecture/design.md`
- Required architecture/database decisions:
  - 继续由 `yudao-module-rental` 拥有目录、映射、订单标准化、转换和历史补建。
  - 使用增量 migration 增加语义明确的渠道商品/SKU 字段、商品规则、备注快照/
    变更审计、订单准备状态、必要索引、菜单和权限；不修改已执行 migration。
  - 复用 `rental_device_category`、`rental_device_model`、`xianyu_order`、
    `xianyu_product`、`xianyu_product_sku`、`xianyu_product_mapping`、
    `rental_order`、`rental_order_item`、`rental_schedule` 和
    `rental_device_assignment`，在设计阶段明确增量列和约束。
  - 规则和映射必须租户隔离，并以内部 `shop_id` 加闲鱼 `item_id` 建立唯一边界。
  - 转换、重评和历史补建必须幂等、可重试、可审计，不在日志中输出原始载荷或客户隐私。

## Frontend-Backend Data Flow Impact

- Foundation spec: `openspec/specs/frontend-backend-data-flow/design.md`
- Required data-flow decisions:
  - 新增配置读取、目录维护、商品规则维护、同步 SKU 查询、受影响订单预览/重评接口。
  - 订单同步顺序调整为：持久化原始详情和明确标识 -> 命中过滤则跳过 -> 普通订单
    幂等创建内部订单 -> 解析备注与匹配型号 -> 计算准备状态 -> 完整后允许排期。
  - 商品或 SKU 同步成功、备注变化、映射变化均可触发同一重评服务，不复制转换逻辑。
  - 前端只提交所选店铺、商品、同步 SKU、型号和策略；后端重新校验租户、店铺关系、
    唯一性、SKU 所属关系、履约保护和受影响订单。
  - 配置修改响应返回受影响数量和异步重评结果入口，前端不乐观修改服务器状态。

## Component Architecture Impact

- Foundation spec: `openspec/specs/component-architecture/design.md`
- Cohesion/coupling impact:
  - 新页面负责协调查询、筛选和对话框；目录、商品规则、SKU 映射和备注规范各自成为
    单一职责区域。
  - 展示组件不直接调用 API；类型和请求集中在租赁配置 API 客户端。
  - 后端 Controller 不访问 Mapper；规则匹配、订单补全和履约保护由领域 Service 统一执行。
- Shared extraction requirement:
  - 目录选择、型号标签和设备编号预览继续复用现有 `deviceCatalogModel` 工具。
  - 抽取统一的渠道标识展示、规则表单、SKU 映射编辑和备注模板复制组件。
  - 抽取一个后端订单重评服务，供订单持久化、备注回放、商品/SKU 同步、配置更新和
    历史补建调用。
