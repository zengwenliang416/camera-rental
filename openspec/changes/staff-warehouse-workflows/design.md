# 手机仓务流程完善设计与上线边界

## 实现范围

### 同订单多设备发货

新增可选 `deviceIds`，旧 `deviceId` / `deviceNo` 单设备调用保持兼容。
手机连续扫描，按型号台数校验、设备 ID 去重、保留已扫运单；确认页列出全部设备。
后端锁定渠道订单、租赁订单与明细，再按设备 ID 排序处理，校验 READY、整单实际台数、
已有分配和设备状态；复用分配与出库服务。最多 100 台，同一订单使用同一运单。

闲管家官方文档 `api-93586386.md`（2026-09-22 当次在线读取）只支持单订单/单运单请求。
仍由 `XianyuWriteClient` 发送 POST `/api/open/order/ship`，复用 appid/sign/timestamp 签名。
内部只保存一条渠道发货回执（兼容原运单唯一约束），配送关系关联全部设备。
没有添加渠道分批/多包裹发货，不能把本次实现理解为支持该外部能力。

### 超时、重试与异常

`rental_shipment_attempt` 在渠道写之前通过 REQUIRES_NEW 独立事务提交 SENT，
外层事务回滚不能抹掉已经发送的事实。每个租户/渠道订单只有一个请求保护记录。
渠道明确拒绝或请求在发送前被客户端拒绝时标记 REJECTED，才允许重试；
传输超时、非法响应、HTTP 不明结果保持 UNKNOWN，阻止同订单更换幂等键再次发货。
结果查询优先看本地已提交发货回执，无回执不推断失败。

手机最多执行三次只读结果核对；隐藏/离开页面后忽略晚到响应。长期未确认自动登记
去重的服务端异常。异常接单、记录进度、结单、重新打开均校验版本与负责人。
处理记录不会自行补录发货或修改订单：渠道已发货、本地回执缺失需核对实物、渠道及
本地分配后通过已有授权补录流程处理；多设备复杂补录仍需运营审核。

### 实物收货、检测与维修

`/rental/device/receive` 接收 deviceId、assignmentId，锁设备和当前有效租赁轮次；
写 returnedAt、PENDING 检测事实并创建 RETURN_INSPECTION 系统锁。
保持 RENTED / DISPATCHED（尚未完成本轮履约），不提前释放排期或恢复可租。
已收同轮次重复请求幂等；设备已进入其他出库轮次则拒绝。

`/rental/staff/inspection` 校验型号检测模板、配件应有/实有数量、照片归属和幂等键，
记录结构化检测证据，再复用 `/inspect` 生命周期实现。
通过才完成分配、收窄排期及恢复 AVAILABLE；失败保持 MAINTENANCE 和系统维修锁。
同轮次维修后可复检，保留每次检测历史；旧 `/return` 合并回仓检测接口继续兼容。

检测模板由有 `rental:device:update` 权限的员工配置；未配置时沿用五项默认清单。
配件实收数量与应有数量不一致，即使客户端勾选 PASS，服务端也判为不通过。
照片最多每次提交 6 张、每轮次授权 12 张，每张 5 MB，使用 infra 预签名上传和确认接口；
仅返回短期签名查看地址，不把照片或客户信息写入普通访问日志。

### 作业、排期、盘点、诊断

- `/rental/staff/tasks`：后端按 Asia/Shanghai 日期筛选今日应发、计划回仓、超期、
  已收待检测及待维修队列，并在同一筛选条件下计数。返回设备/订单入口，避免手机逐页扫全部订单。
- 日期找设备复用现有分配候选规则：状态、启用、有效排期、锁和物流风险统一检查，
  每型号最多核对 100 台，属于查询预览；真实分配仍在事务内复核。手机增加日期条和紧接下一单提醒。
- 盘点按仓位形成设备快照，连续扫码保存实盘记录和差异；不直接改库存状态。
  结束盘点后，只有具备 `rental:device:update` 的员工可逐台确认移入仓位，且原仓位/状态
  必须仍满足检查条件。未盘设备不会自动报废、停用或删除。
- 扫码诊断分别显示连接、扫码读取和服务器核验，复制版本/机型/时间/本机编号及脱敏结果。
  本机诊断编号用于沟通定位，不冒充服务器请求追踪 ID；诊断不触发业务写入。

## 新 API 与权限

- `/rental/staff/tasks`、`available-devices`、异常列表：`rental:schedule:query`。
- 异常登记/处理：`rental:device:assign` 或 `rental:xianyu:ship`。
- 盘点查询、检测模板/历史查询：`rental:device:query`。
- 收货、检测、照片授权确认、盘点登记：`rental:device:assign`。
- 型号模板配置、盘点仓位调整：`rental:device:update`。
- 发货结果查询：`rental:xianyu:ship`。

沿用统一租户拦截器、认证和审计。关联对象通过租户范围的 Mapper 查询，不接收客户端 tenantId。
新增结构位于 `20260922_060_staff_warehouse_workflows.sql`，已登记迁移清单。

## 发布与回滚

先部署后端并执行新增表迁移，再发布手机 1.1.0（110）。不得让新版手机先依赖不存在的接口。
旧 1.0.6 可继续用旧接口；表迁移不删除或重写历史订单。代码回滚保留新增审计/检测/盘点表，
不删除 SENT 请求保护记录，不将未完成检测的设备批量恢复可租。
本次本地测试不执行真实渠道发货、不更新生产订单、不发布下载页。

## 窄屏操作布局

工作台入口使用三列固定网格，作业状态使用五个短标签同屏展示并在下方显示完整队列名。
检测、异常和盘点的并列动作使用等宽两列，主提交单独一行，配置类次要动作分区显示。
按钮最小高度 44px，长文案允许增加高度；保留现有主题变量和系统深色模式。
页面导航与图片预览使用脚本中的显式 uni API 调用，避免别名绕过 uni-app 跨端编译替换。
