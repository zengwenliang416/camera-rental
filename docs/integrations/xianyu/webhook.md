# 闲管家推送回调

## 接收范围

推送由后端接收，不能由 Web 或 uni-app 客户端接收。当前文档覆盖：

- 商品回调通知。
- 商品推送通知。
- 订单推送通知。

具体回调字段、签名或身份校验方式必须以对应官方 Markdown 为准。

## 处理流程

```text
接收请求
  ↓
校验签名 / 身份
  ↓
保存脱敏原始请求和幂等键
  ↓
快速返回平台要求的响应
  ↓
异步拉取详情并处理业务
  ↓
记录成功、失败、重试和人工重放信息
```

回调线程不得执行耗时的订单转换、排期计算或完整详情同步。

## 安全要求

- 生产和测试回调地址隔离。
- 回调地址使用 HTTPS。
- 校验失败的请求不得进入业务处理。
- 重复推送不能重复创建订单。
- 原始请求保存时脱敏，完整敏感内容不得进入普通日志。
- 回调失败必须可人工重放。

## 待补官方字段

| 项目 | 状态 |
| --- | --- |
| 回调 URL 和 HTTP 方法 | 待从目标 Markdown 补录 |
| 签名 / 身份校验字段 | 待从目标 Markdown 补录 |
| 平台成功响应格式 | 待从目标 Markdown 补录 |
| 推送重试行为 | 待从目标 Markdown 补录 |

## 测试

- 签名失败。
- 重复推送。
- 无法解析的原始请求。
- 快速响应与异步处理分离。
- 失败重试和人工重放。
