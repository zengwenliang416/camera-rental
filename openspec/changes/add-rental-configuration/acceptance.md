# Acceptance Criteria: add-rental-configuration

## User-Visible Criteria

- “租赁运营”下存在独立“租赁配置”菜单，具备权限的管理员可维护设备目录、渠道商品
  规则和闲鱼备注规范。
- “租赁设备”页仍可按大类/型号筛选并在创建设备时选择目录，但不再显示新增大类或
  新增型号的快捷入口。
- 配置页可以新增、编辑、启停设备大类和型号，并维护型号的设备编号前缀。
- 管理员可以为一个店铺的闲鱼商品选择 `CREATE_RENTAL` 或 `CONFIG_SKIPPED`。
- 单型号商品只配置一个设备型号；多型号商品只能从已同步 SKU 列表逐项配置型号。
- 多型号 SKU 未同步或未配置时，页面明确显示“待型号配置”，不显示或保存猜测结果。
- 页面分别标注闲管家商品 ID、闲鱼商品 ID、闲管家 SKU ID 和闲鱼 SKU ID。
- 页面提供三种备注基础模板、八种特殊情况说明和一键复制。
- light/dark、`zh-CN`/`en`、桌面和窄屏下均可完成核心配置流程；loading、empty、
  error 和 permission 状态不会显示为正常空表。

## System Criteria

- 订单详情的 `product_id`、`item_id` 和 `sku_id` 分别落入语义明确的字段；不存在
  `product_id -> item_id` 或 SKU 标识之间的回退。
- 商品详情的 `publish_shop.item_id` 和规格接口的 `xy_sku_id` 被保存，并可与订单
  中的闲管家 `product_id`/`sku_id` 精确关联。
- 普通渠道订单详情持久化后，即使无备注、备注失败、无型号或日期不完整，也只创建
  一个内部租赁订单和明细，并保存全部实付金额。
- 同一渠道订单重复同步、推送重放、手工重评或历史补建不会重复创建内部订单。
- `CONFIG_SKIPPED` 订单保留渠道订单、原始载荷和实付金额，但不解析备注、不创建
  人工复核、不创建内部租赁订单、不生成排期。
- 29 个初始过滤商品严格按对应店铺匹配；任一店铺无法唯一解析时不会产生跨店规则。
- 单型号映射只按 `shop_id + item_id` 命中；多型号映射必须再精确命中订单中的闲管家
  `sku_id`，不回退商品级型号。
- 型号、租期或占用日期未完整时，分配/排期接口拒绝执行并返回稳定原因码。
- 新备注成功时更新同一订单的计划日期；新备注无效时保留上一次有效日期。
- 已分配、已出库、已回仓或已检测记录不被配置或备注自动覆盖。
- 续租在无冲突时延长当前设备预计占用，有冲突时进入复核；早退在检测完成前不释放占用。
- 换机保留原分配并创建替代分配历史，不能直接覆盖原 `device_id`。
- 配置变化只自动改写尚未分配的型号；已分配或已出库订单出现不一致时进入复核。

## Data Criteria

- 增量 migration 使用新的迁移编号，不修改 `001` 至 `051` 等历史 migration。
- 外部长整型标识在后端和前端契约中使用字符串，并为店铺、商品、SKU、状态和待补建
  查询建立必要索引。
- 商品规则在当前租户内以 `shop_id + xianyu_item_id` 唯一；多型号子规则以商品规则
  加闲管家 `sku_id` 唯一，并校验 SKU 确实属于该商品和店铺。
- 原始备注、解析版本、每次解析结果、有效计划快照和变更原因可追溯。
- 历史补建可重复运行，输出扫描、跳过、创建、更新、冲突、失败和待复核计数。
- 已有内部订单、分配、排期、出库、回仓、检测和结算历史不会因过滤或映射回填而删除。

## Component Criteria

- Reusable components, hooks, utilities, or services named in
  `component-impact-map.json` are extracted instead of duplicated.
- 租赁设备页和租赁配置页共用目录类型、选择器模型和型号标签逻辑，不各自维护一份。
- 商品规则列表、SKU 映射编辑和备注模板区不直接导入请求客户端。

## Verification Surfaces

- Facticity: 用当前闲管家订单详情、商品详情、商品规格文档核对字段来源，并用脱敏
  Fixture 证明 `product_id/item_id/sku_id/xy_sku_id` 的对应关系。
- Static: 后端编译、管理端 `pnpm ts:check`、migration 静态检查、权限和 i18n key 检查。
- Unit: 标识解析无回退、单/多型号精确匹配、即时建单、过滤跳过、备注保留、重评幂等、
  排期冲突、续租/早退/换机保护和历史补建。
- Redteam: 跨租户/跨店 SKU、伪造 SKU、未知 item、禁用规则、配置竞态、重复回放、
  已履约订单逆转和原始隐私泄露。
- E2E: 管理员配置目录和单/多型号规则，普通订单即时建单，后补备注/映射自动更新，
  过滤订单跳过，已分配订单不被自动改写。
- Sensory: light/dark、`zh-CN`/`en`、桌面/窄屏、loading、empty、error、permission、
  SKU 展开、确认对话框和复制反馈。

## Unresolved Gaps

- None.
