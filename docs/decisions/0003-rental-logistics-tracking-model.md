# 0003 - 租赁物流追踪模型与快递100边界

## 状态

Accepted (2026-07-31)

## 背景

现有 `rental_device_shipment` 记录一次闲鱼渠道发货和单台设备出库审计，无法表达
一单多包裹、一包多设备、退回/换机物流、完整轨迹快照和异步供应商处理。

## 决策

1. `rental_device_shipment` 继续表示渠道发货操作审计，只增加可空 `delivery_id`。
2. `rental_delivery` 表示真实包裹，一单多包裹、一包多设备。
3. 寄出、客户退回、换机寄出和换机退回分别创建 Delivery，不覆盖历史运单。
4. 发货事务只写本地 Delivery、关系和 Outbox，不调用快递100。
5. 快递100订阅推送为主，主动查询只做首次预览和补偿，并受后端限频。
6. 回调验签后先持久化加密 Inbox，再异步转换为 Provider 无关完整轨迹快照。
7. 相同完整快照不增加版本；终态不能被迟到的非终态数据回退。
8. 排期中心只读取本地物流摘要和轨迹，不直接访问供应商。
9. 物流签收不修改设备可用性，设备仍需回仓、验收和检测。
10. Provider 配置默认关闭；公共配置与多组命名凭据分表保存，凭据、回调内容、
    手机号和安全 token 使用加密字段。
11. Delivery 首次执行 Provider 任务时稳定绑定一组当前租户的启用完整凭据；仅当
    绑定凭据停用、删除或不完整时重新选择。
12. 快递100配置仍归在“租赁运营”菜单下，但配置查询、修改、凭据管理、验证和
    历史回填仅允许 `super_admin`；普通员工不显示该配置页面。排期中心和员工业务
    页面只读取物流跟踪结果，不读取 Provider 配置或凭据。

## 后果

- 新增 Delivery、设备关系、轨迹、Inbox、Outbox、承运商映射、Provider 公共配置
  和 Provider 多凭据表。
- 快递100 SDK 类型只能存在于 `integration.logistics.kuaidi100`。
- 历史回填、订阅和查询均由显式运营任务执行，不进入结构 migration。
- CI、普通单元测试和本地默认启动不得访问真实快递100。
