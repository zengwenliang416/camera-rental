# 闲管家开发规则（按需读取）

闲管家是闲鱼店铺、商品、订单、售后和推送的外部渠道。完整业务规则见：

- [闲管家领域规则](../domain/xianyu-integration.md)
- [官方文档入口](../integrations/xianyu/source.md)
- `https://s.apifox.cn/3ac13d69-5a38-4536-ae9b-a54001854ef8/llms.txt`

## 开发前置条件

开发或修改任何闲管家功能前必须：

1. 重新读取当前在线 `llms.txt`。
2. 从索引定位本次实际使用的接口。
3. 打开目标接口完整 Markdown 文档后再写代码。
4. 记录请求地址、方法、认证 / 签名、字段、响应、错误码和限制。
5. 文档与旧代码冲突时，以当前在线文档为准，并记录兼容性影响。

不得仅凭记忆、历史聊天、旧代码或字段名称猜测接口行为。

## 集成边界

闲管家客户端统一放在后端租赁模块的：

```text
yudao-module-rental-biz/src/main/java/.../module/rental/integration/xianyu/
```

建议按 `client`、`config`、`dto`、`convert`、`webhook`、`service`、`enums` 和
`exception` 分层。业务 Service 不得直接拼签名或发送 HTTP。

新增同步入口、配置重评和历史补建应复用
`RentalChannelOrderReconciliationService`，计划变更遵循
`RentalFulfillmentUpdateGuard` 的履约保护，不复制另一套转换规则。
普通 READY 门槛和已批准的受控发货例外以领域文档及当前代码为准；
不得为修复一个待补租期订单而全局放宽状态校验。

## 只读与写操作

默认只实现和测试只读能力：店铺、商品、订单、售后和快递公司查询。

创建 / 编辑商品、修改库存、上下架、删除商品、订单发货、订单改价和同意 /
拒绝退款均属于写操作。执行写操作必须有用户明确授权、目标店铺二次校验、
幂等控制和审计记录，默认只允许测试店铺，自动化测试不得操作真实店铺。

## 凭据与日志

闲管家商家凭据、接口地址、Webhook、写开关和同步参数统一由管理端按租户维护，
加密保存到 `xianyu_application`。服务端不得再从 `XGJ_*` 环境变量读取或兼容
商家业务配置。数据库字段加密主密钥仍由基础设施配置注入，不属于管理端业务配置。

不得把真实 AppKey、AppSecret、签名、完整请求头、客户手机号、地址或身份证
写入 Git、前端、普通日志、测试 Fixture 或文档。日志和导出必须脱敏。

## 店铺与订单同步

应用和店铺授权必须分开建模。同步订单前先检查店铺授权状态；授权失效时停止
该店铺写操作，保留历史订单和排期，并记录同步异常。

订单同步采用“订单推送 + 定时增量同步 + 订单详情补拉”：

1. 保存未经业务处理的原始推送。
2. 使用外部订单号幂等。
3. 拉取并保存订单详情。
4. 转换为内部租赁订单并解析备注。
5. 进入排期计算或人工复核。
6. 使用安全游标补偿遗漏和状态变化。

必须固定同步边界，处理相同更新时间的多条记录，并区分接收、去重和失败数量。

## 金额与备注口径

- `pay_amount` 作为闲鱼订单实付金额和总租金收入来源。
- 备注为空或解析失败不能导致订单从总租金中消失。
- `seller_remark` 只用于提取发货、收货、计租和发回日期。
- 退款、押金退还和设备赔偿分开统计。
- 金额进入内部系统后使用整数分，日期统一按 `Asia/Shanghai` 处理。
- 明确租期优先；没有明确租期时，收货次日开始计租，发回当天计租。
- 缺少年份时结合订单时间与现有解析规则推断；日期冲突或信息不足时进入人工复核，不得静默猜测。
- 每日分摊精确到分，总和严格等于实付金额，分币余数放到最后一个计租日。

## 原始数据与测试

渠道原始 JSON、标准化字段、转换版本、同步时间和异常原因必须可追溯保存，
支持历史订单重新解析。测试默认使用脱敏 Fixture 或 Mock Server，真实接口测试
必须显式开启、默认只读且不进入普通 CI。
