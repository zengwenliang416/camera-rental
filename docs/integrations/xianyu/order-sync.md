# 闲管家订单同步

## 当前接口快照

已于 `2026-09-01` 根据官方在线 Markdown 复核：

| 接口 | 方法与路径 | 首期用途 |
| --- | --- | --- |
| 订单列表 | `POST /api/open/order/list` | 按时间窗口增量补偿 |
| 订单详情 | `POST /api/open/order/detail` | 按 `order_no` 补全和复核 |
| 订单推送 | 商家配置的 `POST` 回调地址 | 触发详情补拉 |

订单卡密、物流发货和修改价格不在首期只读范围。

## 同步策略

采用“订单推送 + 定时增量同步 + 订单详情补拉”：

1. 保存未经业务处理的原始推送。
2. 使用 `channel + application_id + external_order_no` 幂等。
3. 查询订单详情并保存原始响应。
4. 保存标准化渠道订单及 `goods.product_id`、`goods.item_id`、`goods.sku_id`。
5. 按当前租户和店铺精确检查 `CONFIG_SKIPPED`。
6. 普通已付款订单立即幂等创建同一个内部租赁订单和明细；备注、型号或日期不完整
   只影响准备状态，不阻止订单和实付金额进入内部系统。
7. 保存备注解析历史，按精确商品/SKU 规则补充型号并计算准备状态。
8. 后续详情、备注、商品/SKU 同步和配置变化调用同一重评服务。
9. 使用安全游标补偿推送遗漏和状态变化。

处理策略：

- `CONFIG_SKIPPED`：保留渠道订单、原始载荷和 `pay_amount`，但不解析备注、不创建
  转换复核、不创建内部租赁订单、不生成排期。
- 未配置规则或 `CREATE_RENTAL`：创建内部订单并持续重评。
- 单型号只按 `shop_id + xianyu_item_id` 命中。
- 多型号必须再精确命中订单的闲管家 `sku_id`；不得使用商品级默认型号回退。

备注解析优先级：

1. 明确的 `租期/计租/用机` 日期范围。
2. 明确的发货、收货、发回日期；无显式租期时从收货次日起计租，发回当天计租。
3. 明确写为“某日自提”时，自提日期同时作为出库日期和收货日期。
4. “跑腿”“若干天”等无法唯一确定收货日或计租边界的文本不自动猜测，继续进入人工复核。

## 分页边界

- 订单列表 `update_time` 只允许查询最近六个月内的时间范围。
- `page_no` 范围为 `1..100`，`page_size` 范围为 `1..100`，同一查询条件
  翻页超过一万条会报错。
- 每次运行固定 `update_time` 上界，并把大窗口递归拆成不会触及一万条上限的
  小窗口。
- 保存最后更新时间和稳定的并列订单号游标；处理相同更新时间的多条记录。
- 记录服务端数量、接收数量、去重数量和失败数量。
- 在开始翻页前后比较窗口边界，不能用“当前时间不断前移”的查询。
- 失败时从安全游标恢复，不从不确定位置继续。
- 同一租户的店铺授权同步和订单同步分别使用资源级分布式锁；同类任务互斥，
  但耗时订单同步不会阻塞授权状态刷新。

订单列表请求可包含：

```text
authorize_id
order_status
refund_status
order_time (已废弃)
pay_time
consign_time
confirm_time
refund_time
update_time: [startEpochSeconds, endEpochSeconds]
page_no
page_size
```

同步默认使用 `authorize_id + update_time + page_no + page_size`。状态筛选只用于
专项重放，不作为常规增量游标，避免漏掉状态变化。

订单详情请求：

```json
{"order_no":"<external-order-no>"}
```

## 关键字段

| 外部字段 | 内部用途 | 规则 |
| --- | --- | --- |
| `order_no` | 外部订单号 | 作为幂等键的一部分 |
| `authorize_id` | 店铺授权 | 同步前校验授权 |
| `seller_remark` | 日期解析原文 | 原文必须保留 |
| `goods.product_id` | 闲管家商品 ID | 保存到 `xgj_product_id`，按字符串处理 |
| `goods.item_id` | 闲鱼商品 ID | 保存到 `xianyu_item_id`，按字符串处理 |
| `goods.sku_id` | 闲管家 SKU ID | 保存到 `xgj_sku_id`，按字符串处理 |
| `total_amount` | 下单金额 | 官方明确单位为分，不覆盖实付金额 |
| `pay_amount` | 总租金收入 | 官方明确单位为分，直接按整数分保存 |
| `refund_amount` | 退款统计 | 订单列表明确单位为分；与租金、押金、赔偿分开 |
| `express_fee` | 运费 | 官方明确单位为分 |
| `goods.price` | 商品单价 | 官方明确单位为分 |
| `update_time` | 增量时间 | Unix 秒；与 `order_no` 组成稳定并列游标 |
| `consign_type` | 发货类型 | `1` 物流发货，`2` 虚拟发货；内部不得据此猜测租赁交付完成 |
| `receiver_name`、`receiver_mobile`、地址字段 | 发货联系人快照 | 官方仅在待发货状态返回；后续已发货详情缺失时保留最近一次非空值 |

订单列表响应包含 `list`、`count`、`page_no` 和 `page_size`。订单详情中的收货
姓名、手机号和地址仅在待发货状态返回；首次取得后保存为渠道订单快照，状态变化
后的空字段不得清除历史非空值。这些字段只进入受控原始 / 标准化存储，不进入
普通日志、普通导出或测试 Fixture。已有 `rental:xianyu:query` 权限的管理端订单
接口可返回完整收货快照和卖家备注；待发货搜索继续要求
`rental:xianyu:ship`，并支持按订单号、收货人姓名或完整手机号查询。两个接口都
不得返回 `detail_json`、`goods_json`、支付号、凭据或签名。

本地会严格校验分页字段为整数、页码/页大小边界、请求与响应页元数据一致，并
根据 `count/page_no/page_size` 校验当前页应返回的精确条数。手工窗口开始时间
早于当前 `Asia/Shanghai` 时间六个月时会在发起远程请求前拒绝。

增量窗口存在重叠时，若本地订单已有详情载荷且 `source_updated_at` 不早于列表
返回的 `update_time`，该订单计为去重成功并跳过重复详情请求；发生变化的订单
仍按官方流程逐单补拉详情。

后台遗留详情补偿只选择 `detail_json` 缺失且具备非空 `external_order_id` 的订单，
并按 `source_updated_at`、本地 `id` 倒序优先补最新更新的订单。服务层会再次跳过
空白外部订单号，避免用空 `order_no` 调用订单详情接口，并继续处理同批次其他
有效订单。该补偿路径不推进订单分页 cursor。

订单列表页响应会以 `ORDER_PAGE` 写入受限原始载荷表。管理员使用单独的
`rental:xianyu:replay` 权限重放 `ORDER_PAGE` 时，只从本地持久化页解析订单号和
更新时间，按同一“本地详情是否已是最新”的规则补拉缺失或过期详情；该重放不会
推进订单分页 cursor，也不会执行任何第三方写操作。详情响应仍以 `ORDER_DETAIL`
保存，详情 raw payload 重放只重建本地订单详情，同样不推进 cursor。

`pay_amount` 的在线 OpenAPI 类型为 `int64`。内部订单表必须使用 `BIGINT` 分值列，
不能以 32 位 `INT` 截断大额订单。

订单详情不提供可作为本地权威来源的闲鱼 `xy_sku_id`。该字段只能来自商品详情或
商品规格同步的 `sku_items[].xy_sku_id`，并与同一商品的闲管家 `sku_id` 一起保存。
缺失任何标识时保持空值，不允许 `product_id -> item_id`、`sku_id -> xy_sku_id`
或相反方向的回退。

## 状态基线

当前订单状态：

```text
11 待付款
12 待发货
21 已发货
22 已完成
23 已退款
24 已关闭
```

当前退款状态：

```text
0 未申请退款
1 待商家处理
2 待买家退货
3 待商家收货
4 退款关闭
5 退款成功
6 已拒绝退款
8 待确认退货地址
```

外部状态只映射到渠道订单状态，不直接覆盖内部租赁订单状态机。

## 备注解析

- 明确 `#租期7.25-7.27#` 时优先使用明确租期。
- 只有收货和发回时，收货次日开始计租，发回当天计租。
- 发货日期不参与计租天数。
- 缺少年份时结合订单时间推断。
- `SELLER_REMARK_V6` 支持完整年份、中文日期、可选井号、计租 / 用机同义词，
  以及出库、到货、归还等物流同义词。明确的“某日自提”同时作为出库日和收货日；
  日期与“自提”之间可以包含不含数字的短姓名或城市描述，缺少发回日时仍保持
  `PENDING / MISSING_RETURN_DATE`。
- 对 `发货7.30 7.31 发回8.10` 可把中间日期确定为收货日期；对历史固定模板
  `发货7.30 收货7.31 发货8.10` 可把第三个“发货”确定为发回日期。其他歧义
  格式不得按位置猜测。
- 备注为空、缺少订单参考日期或关键物流日期时，解析状态记为 `PENDING`，
  不创建人工复核。已可靠识别的计租和物流日期仍保存供管理端复核，但不得自动
  排机或转换。
- 定时增量同步或订单推送补拉到更新后的详情时，重新解析并覆盖租期字段。
- 当前解析版本为 `SELLER_REMARK_V6`。物流日期早于订单日期时记为
  `FAILED / LOGISTICS_DATE_BEFORE_ORDER`；收货、发回等日期顺序冲突时记为
  `FAILED / INVALID_LOGISTICS_RANGE`，不再通过无条件跨年推断修正。
- 解析版本升级后，订单增量任务会分批重算旧版本记录并覆盖租期与物流日期字段；
  重算成功后重新触发内部订单转换并关闭已失效的开放复核。
- 原始备注、解析版本、结果和错误原因一起保存。

内部订单准备状态：

- `WAITING_MODEL`：商品或 SKU 没有精确型号映射。
- `WAITING_REMARK`：计租或占用日期尚不完整。
- `REVIEW_REQUIRED`：新计划与已分配/已出库事实冲突，或需要人工处理。
- `READY`：型号、计租周期和设备占用周期完整，可进入分配和排期。

设备分配和发货必须消费 `READY` 状态。发货工作台不能通过操作员临时选择设备来
创建或覆盖渠道商品规则；型号配置只能在租赁配置页按店铺和闲鱼商品/SKU 精确维护。

新备注解析成功时更新同一内部订单的计划日期；空白、不完整或失败备注保留最后一次
有效计划。已分配但未出库的日期变化先检查冲突；已出库后的续租只在无未来冲突时
延长预计占用；早退在实际回仓且检测完成前不释放占用；换机必须保留原分配并创建
替代历史。备注不能生成实际出库、回仓、检测、退款或结算事实。

## 测试

- 分页和安全游标。
- 外部订单幂等。
- 多店铺隔离。
- 详情补拉失败重试。
- `ORDER_PAGE` 重放不推进 cursor，且保留成功 / 失败计数。
- 六个月边界和一万条窗口拆分。
- 相同 `update_time` 下多个订单不丢失。
- 备注信息不足时保持 `PENDING`，已识别日期可供复核；后续详情更新可转为
  `SUCCESS`。
- 备注解析待定或失败仍计入总租金。
- 分币、跨月和跨年分摊总额守恒。
管理端历史备注重解析与定时订单同步复用租户级订单锁
`camera-rental:xianyu:sync:{tenantId}:order`。同步运行期间不允许并发启动重解析，
避免同一渠道订单被重复解析、转换或覆盖；管理端应提示稍后重试。
