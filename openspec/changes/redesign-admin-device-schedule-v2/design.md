## Context

现有排期页面调用 `/rental/schedule/page`，以排期记录为分页单位，无法稳定展示几百台
设备、跨月长租、待分配订单和物流过程。后端已有排期、设备、分配、渠道订单和
快递100跟踪能力，最终分配服务已经具备事务、锁和冲突重查，但缺少面向工作台的
聚合读模型。

已批准原型位于 Open Design 本地项目
`camera-rental-admin-schedule-v2/camera-rental-schedule-v2-prototype.html`，最终
评审版本为 `device-search-v7`。生产实现必须遵循当前 Element Plus 管理端规范，
不能直接复制原型中的独立 HTML 状态或演示数据。

## Goals / Non-Goals

**Goals:**

- 提供单仓、设备分页的 14/30/90 天排期时间轴。
- 把设备、有效占用、订单明细、物流和检测状态组合成服务端权威读模型。
- 支持待分配和部分分配订单、候选推荐、冲突刷新及最终事务分配。
- 提供订单、设备和物流右侧抽屉。
- 支持数百设备规模且避免 N+1 数据库和外部物流调用。

**Non-Goals:**

- 不复制员工端的扫码、出库、回仓、检测和维修写流程。
- 不实现跨仓调拨或仓库选择。
- 不让前端推断权威冲突、候选或释放状态。
- 不在第一阶段建立独立持久化冲突事件表。
- 不修改订单计租金额或渠道同步口径。

## Decisions

### 1. 使用单个工作台聚合接口驱动首屏

新增 `GET /admin-api/rental/schedule/workbench`，一次返回查询窗口、指标、设备分页、
设备条带、待分配摘要和异常摘要。以设备而非排期行分页，保证每台设备的时间轴完整。

替代方案是前端并发调用设备、排期、订单、报表和物流接口后拼接。该方案会让前端
成为排期真相来源，并产生分页错位和 N+1 风险，因此拒绝。

### 2. 读模型按批量本地数据组合，物流轨迹按需加载

工作台列表只读取本地 Delivery/物流快照和风险，不直接请求快递100。点击物流抽屉
后复用现有 tracking detail 和 refresh 接口。后端按当前设备页批量查询关联记录。

### 3. 候选推荐和最终分配分离

候选接口按订单明细型号、完整占用区间、设备启用状态、设备状态、有效排期、物流/
检测风险和锁定策略返回资格及稳定原因码。候选结果只用于决策；最终写入继续调用
现有 `POST /rental/device/assign`，在事务中锁行并重新检查。

### 4. 占用释放使用实际生命周期覆盖预计边界

计划排期仍保存预计 `occupyEndDateExclusive`。工作台的当前可用性必须结合实际
出库、返程、回仓、检测和维修状态：回仓未检测完成不能释放；检测不通过进入维修/
隔离。后端返回预计释放和实际释放状态，前端不自行修改条带。

### 5. 前端按协调层和领域组件拆分

`index.vue` 管理查询、请求和选中状态；指标、过滤、时间轴、待分配、推荐、异常和
三个详情抽屉独立。日期窗口与条带裁剪放在 `scheduleModel.ts` 并用 Node 测试覆盖。

### 6. 使用分类持久化设备锁定

新增 `rental_device_lock`，统一表达 `ORDER_HOLD`、`RETURN_INSPECTION`、
`MAINTENANCE` 和 `MANUAL_HOLD`。记录设备、原因、关联订单/明细、创建人或系统来源、
开始时间、计划结束、实际解除、状态和租户审计字段。

活动锁定统一从候选中排除，最终分配事务再次检查。订单预留和主管人工保留可由具备
权限的运营人员创建或解除；回仓待检测和维修隔离由设备生命周期自动创建、解除，
普通人工操作不得绕过。相比把四类状态分散在设备状态和前端标签中，统一记录可提供
时间轴、审计、自动过期和稳定候选规则。

## Risks / Trade-offs

- [聚合查询数据量较大] → 设备服务端分页，限制 90 天最大窗口，批量查询并增加必要索引。
- [候选在确认前失效] → 候选只作建议，最终分配事务重查并返回稳定冲突码。
- [预计释放与真实生命周期不一致] → 明确返回计划与实际状态，回仓检测完成前保持占用。
- [物流刷新拖慢首屏] → 首屏仅读本地快照，刷新只在详情抽屉按用户操作触发。
- [锁定与设备生命周期漂移] → 回仓、检测、维修和人工锁定写操作共用锁定 Service，
  并增加一致性测试与异常扫描。
- [旧报表利用率与实时指标口径混淆] → 工作台指标按当前窗口计算，经营报表继续使用
  独立历史统计接口并标注口径。

## Migration Plan

1. 先增加只读 VO、Mapper 批量查询、聚合 Service 和测试，不改变现有接口。
2. 增加待分配订单、候选和设备详情接口，继续复用现有分配写接口。
3. 前端切换到 V2 工作台，并保留现有路由名和报表跳转参数兼容。
4. 添加独立增量 migration、设备锁定权限和 Service，不改历史 SQL。
5. 部署后验证旧 `/rental/schedule/page` 仍可用，再按后续决定清理过时接口。
