# Acceptance Criteria: redesign-admin-device-schedule-v2

## User-Visible Criteria

- 运营人员打开现有设备排期菜单后看到与管理端视觉一致的设备排期 V2 工作台。
- 页面不显示仓库选择器；当前租户的设备统一在一个设备列表和时间轴中查询。
- 用户可在 14、30、90 天视图间切换，并前后移动窗口或回到今天；跨月、跨季度
  和几个月的长租条带连续显示，窗口外部分使用延续标记。
- 用户可按设备编号、序列号、型号、设备状态和物流状态搜索数百台设备，并使用
  25、50、100 台服务端分页。
- 时间轴明确区分计租周期和设备占用周期；页面日期不显示数组、逗号日期或内部
  右开边界。
- 点击设备、有效占用条、待分配订单或异常项会打开右侧抽屉，展示对应订单、设备、
  物流过程和预计释放信息。
- 待分配订单展示所需、已分配和剩余数量；部分分配后仍保留在队列。
- 候选设备显示可选或排除理由。确认分配发生并发冲突时，页面刷新候选并要求用户
  重新确认，不显示虚假成功。
- 去程运输、客户持有、返程运输和回仓待检测均显示为占用；仅检测完成或明确维修/
  隔离结果后更新可排状态。
- 页面不提供扫码发货、退回登记、入库检测或维修执行入口。
- light/dark、`zh-CN`/`en`、加载、空、错误、无权限和窄屏状态均无不可恢复的
  布局或原始翻译 key。

## System Criteria

- 工作台所有管理接口验证 `rental:schedule:query` 或更细粒度写权限，并遵循租户
  隔离。
- 日历接口按设备分页而不是按排期行分页，返回同一窗口的设备条带和窗口摘要。
- 服务端使用占用半开区间判断重叠；候选冲突不写入有效排期。
- 候选服务只返回与订单明细型号匹配、启用且在完整占用周期内可分配的设备，并
  返回稳定的排除原因码。
- 最终分配继续在事务中锁定设备和订单明细、重查有效排期并幂等写入。
- 指标、可用性、利用率、待分配数量、异常和预计释放均由后端返回；前端只格式化。
- 工作台批量关联物流摘要，设备详情按需读取轨迹；列表查询不得产生设备数量级
  的外部快递100调用。
- 物流刷新复用现有受权限保护的刷新接口，并返回安全、脱敏的快递信息。
- 回仓但未检测完成的设备不得进入候选推荐或可排设备数量。
- 活动的订单预留、回仓待检测、维修隔离或主管人工保留锁定均阻止候选推荐；最终
  分配事务必须再次检查活动锁定。
- 运营人员只能创建和解除订单预留、主管人工保留；回仓待检测和维修隔离必须由
  对应检测或维修流程自动创建和解除。
- 创建、解除和自动更新设备锁定均记录操作人或系统来源、原因、时间和关联业务。

## Data Criteria

- 工作台复用 `rental_device`、`rental_order`、`rental_order_item`、
  `rental_schedule`、`rental_device_assignment`、`rental_delivery`、
  Delivery 设备关系、物流快照和检测/维修记录。
- 查询使用必要的租户、设备、状态、日期和订单索引；不得通过删除或改写历史排期
  修复显示问题。
- 订单、设备、物流和客户信息遵循现有授权范围；普通时间轴和指标不展示完整手机号、
  地址或渠道原始 JSON。
- 使用增量 migration 新建 `rental_device_lock`，记录锁定类型、原因、关联订单/
  明细、操作人、开始、计划结束、实际解除、状态和租户审计字段。
- 查询活动锁定和按设备/时间窗口查询锁定必须具备租户、设备、状态和日期索引；
  同一设备相互冲突的活动锁定由事务和锁保证不会并发创建。

## Component Criteria

- Reusable components, hooks, utilities, or services named in
  `component-impact-map.json` are extracted instead of duplicated.
- 页面协调组件和时间轴组件分离；前端组件不得导入后端实体或实现候选资格算法。
- 新增生产源文件原则上不超过 450 行，达到 600 行前必须拆分。
- 时间轴纯模型测试覆盖 14/30/90 天窗口、跨月、右开边界显示、左右裁剪、分页和
  搜索参数映射。

## Verification Surfaces

- Facticity: 当前排期、分配、设备、订单、物流和检测模型及权限。
- Static: `git diff --check`、Maven 编译、`pnpm ts:check`、管理端生产构建和
  敏感信息扫描。
- Unit: 日历聚合、设备分页搜索、候选筛选、部分分配、区间边界、指标和物流关联。
- Redteam: 跨租户 ID、无权限详情/刷新、陈旧候选、并发分配、N+1 查询和 PII 泄露。
- E2E: 搜索设备、切换 14/30/90 天、打开三个抽屉、查看待分配并确认分配后刷新。
- Sensory: 管理端浅色/深色、中英文、桌面/窄屏、加载、空、错误、冲突和长租。

## Unresolved Gaps

- 无。
